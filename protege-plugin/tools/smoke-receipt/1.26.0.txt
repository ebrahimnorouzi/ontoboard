What is new in this one: the fifth line. 1.26.0 adds ROBOT > Export terms..., and the two calls
on that path which could fail in a bundle and nowhere else are now exercised in the host:

  - new IOHelper(), which reads resources of its own.
  - ExportOperation.createExportTable, which builds an org.obolibrary.robot.export.Table - and
    Table is one of the four robot-core classes that reference Apache POI. POI is embedded here
    but the log4j 2 API it needs is not, because log4j-api declares its own OSGi Bundle-Activator
    and bnd rejects a second one; log4j-over-slf4j supplies only the log4j 1.x API. So any POI
    class initialisation throws NoClassDefFoundError. The reason export still works is that POI
    is confined to Table.asWorkbook, which write() reaches only for xlsx - and xlsx is the one
    format this plugin does not offer. That was a chain of four inferences, and the line above is
    what turns it into an observation.

The same caution produced a real defect during the same session, caught by a test rather than by
a user: Table.write has no branch for yaml - its bytecode dispatches on tsv, csv, html, html-list,
json and xlsx only - so asking ROBOT to write a .yaml silently produced no file. TermExport now
writes that one itself from Table.toYAML(). A test requiring every offered format to produce a
non-empty file is what found it, and is what keeps the offered list and the writer from drifting.

Asserted in both runs:
  - exactly one ontoboard jar in plugins/ (singleton bundle; two is a collision, not an upgrade)
  - "Starting bundle ontoboard"
  - "Plugin: OntoBoard (1.26.0)" - the version Felix actually resolved, not the one on disk
  - "OntoBoard self-check: PASS 5/5" - an absent verdict fails, because it would mean the hook
    did not run
  - no unresolved constraint, java.* import, UnsupportedClassVersionError or truncated jar
    attributable to our bundle
  - no de.fizkarlsruhe stack frame
  - no OutOfMemoryError at -Xmx500M, which is what Protege.l4j.ini gives a user who
    double-clicks Protege.exe (run.bat hands out -Xmx32G and would have hidden one)

Not asserted, and not claimed:
  - that the OntoBoard tab renders, or that any of the 22 menu items works when clicked. Protege
    restores the previous workspace and a killed process logs no shutdown, so a tab assertion
    here would be an assertion about the last session. Driving the actions is Phase 2's self-test
    bundle.
  - that the remaining ROBOT operations run in-bundle. The self-check covers report and export,
    which are the two whose in-bundle safety rested on an argument rather than an observation.
    13 of robot-core's 21 *Operation classes are still not wrapped at all.
