WHAT THIS RELEASE ADDS

- Zoomed out, a relation's label lay on the line beside it: JGraphX placed it on a slightly
  different line and measured it in a font scaled to the zoom, up to 26 px wider at 21%. A routed
  line's label is now drawn at the router's place, at its size at 100%; on the egg boards no label
  touches a line, a box or a label at any zoom from 10% to 200%.
- A defined class stood apart from its superclass, below every frame: the class a definition starts
  from, C = A and ..., now counts as its superclass for frames, trees and placing. On pizza-bfo after
  Arrange > Outline the defined pizzas stand under pizza.
- A board saved by 1.135.0 kept its patterns' empty frames, which pushed the outline away: such a
  frame is the pattern's again when the board is read - its title a library pattern's name, the
  pattern imported once, and none of the project's classes in it - and an empty one goes. The pizza
  board after Arrange > Outline: 3,035 x 2,792 px with this jar, instead of 8,649 x 7,431.
- On a busy machine routing gave up lines a quiet one routes: its budgets now count the routing
  thread's processor time, and stop on the wall clock at three times the budget.
- Write a test from a question... has a rule that names what the property points to, "Every kind of
  X has some P that is a Y", for a class deep in an imported ontology, where "has some P" passed at
  once; it refuses a data property, for which such a test could never pass.
- Check sheets... and Template... count the same names, the names the sheets use - class
  expressions' too - and a comment is no longer taken for a name. A date written with its datatype in
  a typed column is reported, where it went into the graph as text.
- Find terms searches every label of a term and IAO's alternative label, says which name it found a
  term by, and shows it by the label the board shows. A new module is named after the prefix the
  ontology asks for or a recognisable part of its address - pmdco, not co - and never after another
  import's module; a project that imports a PMDco pattern is offered PMDco and TTO.
- An independent review of these fixes found 16 problems; the important ones and most minor ones
  are fixed, each with a test that failed first. A 1.135.2 candidate had routed boards of up to 500
  lines; that is taken back - the whole board was routed again at every drag - and a board of more
  than 150 lines draws its relations straight, as in 1.135.1 (docs/limitations.md). A second,
  read-only verification of the fixes found 19 more, 2 important: the same ontology read from
  another address got a second module, and a class expression's cell was not read as ROBOT reads
  it. Both are fixed, with 5 minor ones in code and 3 in the notes' wording; 9 minor ones, rare or
  older than this release, are left.


WHAT THIS RECEIPT DOES NOT COVER

- The scripted run sends mouse events to the components directly, so focus, hover, drag and the
  native file dialogs were not exercised with a real mouse on this jar.
- Linux and macOS: not run on this jar; CI runs the unit suite on Linux.
- Protégé's "Ontology sources changed" dialog after a Find terms import, reported once with a 1.135.1
  candidate, did not appear in a live Find terms import with 1.135.1's release nor with an earlier
  1.135.2 build; the probe sends no window-focus events, so a check that a focus change triggers is
  not ruled out.
- A board of more than 150 lines: its relations keep the straight connector, through boxes too.
