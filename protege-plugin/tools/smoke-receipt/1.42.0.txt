RELEASE_DIFF - what will consumers actually see change?

ODK's release_diff target is one line:

  $(ROBOT) diff --labels true --left tmp/current-release.owl --right $(ONT).owl -f markdown -o $@

and tmp/current-release.owl is downloaded from the published PURL. The question it answers is the
one a release pull request has to answer, and a local release cannot: not "what changed since the
release we kept a copy of" but "what changed against what is actually published".

Project > Compare releases... now takes a URL for the 'From' side. Fill it in and the release is
downloaded and compared against the later version chosen; leave it empty and the dated local
releases work as before. The axiom diff can be written to a file, which is the reports/
release-diff.md that target produces.

Everything else was already there: AxiomDiff has had ROBOT's diff with labels on and markdown
output since 1.34.0. What was missing was the two ends - fetching the published artefact, and
writing the file.

A PURL that has never been published resolves to nothing, and that is the common case for a
project's first release. The failure says so in those words rather than reporting a download
error, because "your PURL is not live yet" and "the network is down" call for different actions.
