FIXED IN 1.134.2

- A project that passed Build... in Protege failed its QC workflow on GitHub. Found when the two
  example projects ran QC on GitHub for the first time. ROBOT 1.9.8 failed pizza's check_labels
  on four pattern classes - Concept, Object, Price and Currency - and pizza-bfo's cq5 on the four
  relations a baking must have, has participant to occupies temporal region. Each label those
  checks look for is in an import. Build... inside Protege had passed the same checks, because it
  queries the ontology with its imports merged; the generated Makefile's sparql_test ran robot
  verify on the edit file alone, which sees nothing its imports say. The target now merges the
  imports first, as validate_profile already did, and both projects pass make test under the
  same ROBOT. A project created before 1.134.2 gets the new Makefile from Project > Update
  project files...; until then Build... says the Makefile is not the one OntoBoard generates, and
  names that menu item.

ALSO IN THIS RELEASE

- PatternIndexTest failed CI on main once 1.134.1 was merged, with nothing in the repository
  wrong: an import of a pattern's import did not load over the network, and the test called the
  shipped pattern index stale. It now looks for unloaded imports through the whole imports
  closure, and rebuilds the index once more before calling a row stale.
- The documentation site: the two examples link to their ontologies' documentation pages, and
  each example ends with how to make that page with Build and release > Documentation....
