The three new ones are project-aware: they look for src/ontology, a catalog, imports/. They could
not be covered before because the self-test used an ontology held in memory, and an ontology with
no file has no project - so those actions could only ever have reported "this has not been saved",
which tests nothing. The subject is now a throwaway ODK project scaffolded by the wizard's own
code, into a temp directory, deleted afterwards.

WHAT MADE THAT POSSIBLE, AND WHY IT IS ALSO A CLEANUP

Seven actions carried their own private copy of fileOf(OWLOntology), each asking the *model
manager's* manager for the document IRI. That answers for the ontology Protege has open and for
nothing else, which is precisely why every project-aware action was unusable against anything built
elsewhere. One implementation now lives in OntoBoardAction and asks the ontology's own manager
first, falling back to the model manager.

That is also just more correct: a document IRI belongs to the manager that loaded the ontology, and
for anything Protege owns that manager *is* the model manager's - so nothing changes for the normal
case. Seven copies became one, and the self-test gained three items as a side effect rather than as
the point.
