THE MIRROR - the other half of the import story

1.38.0 made import modules rebuildable by committing the term list. A rebuild still went back to
the network for the upstream ontology every time, which means a refresh needs connectivity, takes
as long as CHEBI takes to download, and extracts from whatever upstream happened to be that
afternoon.

ODK's answer is src/ontology/mirror/: download each upstream ontology once, extract from the local
copy after that. Refresh imports... now does the same, through ROBOT's own MirrorOperation - which
writes the whole imports closure and a catalog, not just one file that then cannot resolve its own
imports.

  Rebuilding reads the mirror when there is one, using an AutoIRIMapper over that directory so the
  source IRI resolves locally with no network at all.
  "Download fresh copies first" replaces the mirror, which is what an upstream release calls for.
  The audit now says which of the two a rebuild would do, before you ask for one.

mirror/ is gitignored by the scaffold and imports/ is not, which looks inconsistent and is not: a
mirror is reproducible from the source each term list records, and CHEBI alone is hundreds of
megabytes. An import module is not reproducible without its term list - which is exactly why 1.38.0
started writing those, and why the modules stay committed.
