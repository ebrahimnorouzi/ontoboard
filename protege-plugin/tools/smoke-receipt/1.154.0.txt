WHAT THIS RELEASE ADDS

- OntoBoard's own engine runs a project's own rules - the rules and settings of its
  <id>.Makefile - as make takes them, when every line the target reaches can be read here, every
  program it calls is one the engine has, and nothing is written outside the project; all asked
  before the first line runs. nfdicore and mwo, which build their import modules so, refreshed
  those imports and ran test_fast by OntoBoard itself and in ODK's container with the same files.
- A project with DOSDP patterns is built and released by OntoBoard itself as ODK builds it.
  DOSDP-Tools 0.19.3 cannot go into the bundle; Build... and Release... offer to download it
  (119 MB, the release ODK's image carries) into .ontoboard/tools in the home folder, unpack it
  only when every library is byte for byte the one in ODK's image, and run it on Java 11 or later.
  ODK's check of the pattern files is GPL-3.0 Python; OntoBoard has its own, held against ODK's
  checker on 191 recorded cases.
- Of ODK's 79 sample configurations, each seeded as ODK seeds it, 74 run every target of Build,
  Release and Refresh imports by OntoBoard itself (48 at 1.153.0), 3 stop only where ODK's own
  make stops too, and 2 need the container (SSSOM, and the db export).
- Build... has a box for each of ODK's four switches (IMP, MIR, PAT, COMP) and shows the make
  command they come to; its targets are named in words with the make target beside them, and
  ODK's deprecated update_repo is no longer offered. Release... shows its make commands.
- Import terms... names ODK's module types in plain words and declares the import with the kind
  chosen; Refresh imports... says which import failed and offers to build it from the copy it
  has; a warning about an undeclared import or imports not merged has a button that applies its
  fix.
- Release... commits the project's new files first, in a commit of their own, so that the
  release's tag holds a new import module and its term list.
- Check this ontology... checks whatever is open - a loose .owl file too - with the reasoner,
  ROBOT's quality report and the label check. Project configuration... shows ODK's own
  description beside each key, from ODK's schema (BSD-3, in NOTICE).
- The board claims and mints under the name Protege 5.6's ID ranges look for, so Protege's own
  "No Id Range Found For Current User" stops once the board has claimed a range.
- A project goes from OntoBoard to ODK and back, both ways, with ODK v1.6.1's container.
- A review of the whole branch found one critical defect, two important and seven minor, and the
  release check by hand four more; all are fixed, each with a test that failed first but one
  test-only finding, shown by its live run. docs/fixed.md has the entries marked 1.154.0.


WHAT THIS RECEIPT DOES NOT COVER

- The scripted runs send mouse events to the components directly, so focus, hover, drag and the
  native file dialogs were not exercised with a real mouse on this jar; the wait cursor while
  Build and Release ask the engine was not seen.
- Linux and macOS: not run on this jar; CI runs the unit suite on Linux and on Windows.
- DOSDP-Tools on Protege 5.5.0, which needs a Java 11 on the machine to run it, was not tried by
  hand; its tests run it with Java 11. On a Java 19 or newer its messages' non-ASCII characters
  come out garbled in the transcript (a deferred minor); the files it writes are not affected.
- OntoBoard's own DOSDP pattern check on patterns unlike the 191 recorded cases: only ODK's
  checker can say, and a project's CI in ODK's image runs that one.
- Podman, and ODK's own tools installed on Linux or macOS: not tried.
- How long each task takes against ODK in Docker on a quiet machine: not measured for this
  release - the machine was never quiet; docs/measurements.md has 1.153.0's measurement and the
  command.
