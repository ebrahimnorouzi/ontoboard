This is the half of Phase 2 the startup check could not reach. SelfCheck proves every action class
loads and constructs under Felix - which catches a dead menu item, and nothing more, because
loading a class is not running it. SelfTestAction wires each action the way Protege does
(setEditorKit, initialise) and calls its run against a scratch ontology built for the purpose, so
what is exercised is the real action in the real bundle with a real editor kit.

Two ways in, one implementation: OntoBoard > Run self-test for a person, and
-Dontoboard.selftest=true for smoke.ps1 -SelfTest. The automated run is what matters - a self-test
only a human can trigger is one that gets skipped before exactly the release that needed it.

IT FOUND A DEFECT ON ITS FIRST RUN

  OntoBoard self-test item: ROBOT > Quality report... | FAILED | threw NullPointerException

QualityReportAction's options field was declared with no initial value, so run() worked only if
configure() had been called first. From the menu it always is, so no user could reach this - and
the honest description is a latent trap rather than a bug anybody was hitting. But every other
action in that package starts its fields at a usable value, this one did not, and the failure
landed two lines after QualityReport.run had itself handled the null perfectly well. It now starts
at ROBOT's defaults.

That is the argument for this kind of test in one paragraph: the defect was invisible to 1133 unit
tests and to a human clicking the item, and it took four seconds to find once something called the
action a way the menu does not.

WHAT IS NOT COVERED, PRECISELY

Six of roughly twenty items. The rest are excluded on purpose and the reasons are in the result:

  Transform... defaults to apply = true. Without its dialog it would compute a relax and push the
  changes through the live session's model manager - not the scratch ontology's. A self-test that
  edits an ontology is not a test.

  Rename IRIs..., Import terms..., Obsolete..., Release..., Build..., Git..., Open from GitHub...,
  New ODK project...: they write files, need a configured project, or reach the network.

  The canvas, notes and collaboration items are Swing surfaces and nothing here opens a window.

So this does not "drive the menu". It drives the six read-only ROBOT operations, in the host, and
says so.
