The sixth line is what this release adds. ROBOT > Explain... answers the question a curator has
when the reasoner goes red - which axioms are responsible, across every unsatisfiable class at
once, ending with ROBOT's summary of which single axiom appears in the most justifications.
Protege's explanation workbench explains one entailment you have already located and clicked;
twelve unsatisfiable classes is twelve investigations there and one table here.

Why it needed a host check of its own. The explanations come from owlexplanation-2.0.0.jar, which
this bundle embeds. ROBOT's own formatter, ExplainOperation.renderExplanationAsMarkdown,
constructs uk.ac.manchester.cs.owl.explanation.ProtegeExplanationOrderer - a class from Protege's
explanation-workbench plugin. This bundle embeds a copy of that too, AND Protege exports the same
package from its own bundle: two copies of one package, resolving differently depending on what
else the user has installed. Explanations therefore renders the axioms itself with the OWL API's
Manchester renderer and never touches that class.

It does use ROBOT's renderAxiomImpactSummary, because javap shows its only dependency is that same
OWL API renderer - checked rather than assumed. But "checked rather than assumed" is an argument
about a classloader, and an argument about a classloader is exactly what was wrong about the
quality report for nine versions. Hence the self-check: a three-axiom ontology with two disjoint
parents and one child that inherits from both, explained with ELK, in the host, at startup.
