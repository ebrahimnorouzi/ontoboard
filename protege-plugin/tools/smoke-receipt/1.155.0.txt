WHAT THIS RELEASE ADDS

- Release... asks the reasoner chosen in its form - the project's own reasoner:, else HermiT;
  the form says what ELK misses - before anything is built, on every route: OntoBoard's engine,
  ODK's container, ODK's own tools. An inconsistent ontology or a class that can have no members
  stops it, with the explanation; there is no way past. A reasoner that does not finish within
  three minutes is said and the person decides, recorded as not checked; an import that did not
  load stops it by name. The reasoner chosen is ODK's REASONER= for that release.
- Each release has its record, releases/<v>/RELEASE.md and the tag's message: what made it and
  with which versions, the reasoner and its verdict, ODK's quality report by rule, the OWL 2 DL
  profile, the measurements, each import's version, and what changed. An ontology in no project
  gets one too. History... shows a release's record and Compare releases... how each was
  checked.
- A release file of an ODK project - the root <id>.owl and its siblings, anything under
  releases/ - is said for what it is when opened, and the pattern library, Import terms...,
  Refresh imports... and Release... refuse to write beside it, offering the edit file.
- A row of the quality report, and of every result naming a term, leads to the term: in
  Protege, and on the board.
- All 162 library patterns curated, each change listed in the pattern; PatternQualityTest holds
  every one to the quality report at ERROR with ODK's default profile, a label on every term it
  declares, and HermiT's consistency and coherence. The 119 patterns from the ODP portal have no
  licence: none could be found for the portal, and none is written that nobody stated.
- The board: data properties as rows of their class's box, object properties as arrows, a
  property drawn only when something uses it; the Properties panel; Board settings for each
  kind's colours, shapes and lines and for the arrangement, kept for a person or a project.
- nfdicore and MWO developed further and released by OntoBoard alone, their own release.sh run
  by the engine line by line; RealProjectsDevelopmentLiveTest repeats it on fresh clones.
- A new project's first ID range is claimed for the person who makes it, so Protege no longer
  asks for one after every pattern imported; Open existing ODK project... asks once where a
  project's ranges name nobody. Readable names are a project's choice - "boiled egg" a class
  BoiledEgg under the project's address, the typed name its label - in New ODK project... and
  in Project > ID ranges...; ODK's namespaces follow; Rename IRIs... > Readable names from
  labels names the numbered terms no release carried.
- Asked by the maintainer on 2026-11-20: History's versions lead to their tags on GitHub; Import
  terms offers every ROBOT method and every ODK module type, each with its own fields; Build and
  Release go on behind while the person works (Keep working), the result opening when done with
  the desktop's notice, and meanwhile anything else that writes the project waits and can stop
  the run; the Spreadsheets menu is Knowledge graph - Edit sheets, Check sheets..., Build from
  sheets...; and the sheet editor no longer freezes Protege on a heading committed or a column
  added (an endless recursion on Swing's thread).
- A review of the whole branch found no critical defect, two important and nine minor; both
  important and seven minor are fixed, each with a test that failed first, and two minor are
  said in docs/limitations.md. The release check by hand found four more, fixed. A second review,
  of the work of 2026-11-20, found no critical defect, six important and six minor: the six
  important and three of the minor are fixed, each with a test that failed first. docs/fixed.md
  has the entries marked 1.155.0.


WHAT THIS RECEIPT DOES NOT COVER

- The scripted runs send mouse events to the components directly, so focus, hover, drag and the
  native file dialogs were not exercised with a real mouse on this jar.
- Linux and macOS: not run on this jar; CI runs the unit suite on Linux and on Windows.
- The release check's reasoner on very large ontologies: measured on MWO, the largest of the
  corpus (HermiT 38 s); a check that runs out of memory stops the release as "could not reason".
- The desktop's notice of a run kept behind: Java's tray notice was not watched for on screen;
  the result opening by itself was.
- How long each task takes against ODK in Docker on a quiet machine: not measured for this
  release; docs/measurements.md has 1.153.0's measurement and the command.
