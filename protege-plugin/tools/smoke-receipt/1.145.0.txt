OntoBoard 1.145.0 - host smoke receipt

The fresh review of 1.144.0 is acted on. Four reviewers read the code, one area each. An
independent checker then reproduced each Critical or Important finding and tried to refute it.
Each change has a test that failed first:
- Keys:
  - A key replaced, forgotten or deleted in Settings stays redacted for the rest of the Protege
    session, in conversations and roles written later. Before, the next save of a conversation
    wrote it in clear.
  - In the benchmark's replies.jsonl, a known key split by a line break is redacted: each text
    is now redacted before it is encoded as JSON.
  - A name and password are removed from every form of address: an empty user, a token used as
    the user, a password that holds "@". GitLab tokens are recognised by their shape.
  - "Nothing answered at ..." no longer shows the end of a password that holds "@".
  - The benchmark refuses a models file that holds a key: in a field such as apiKey, in an
    address's query, or where a variable's name belongs. Git ignores my-models.json and
    results/ where the README puts them.
- Saved conversations:
  - A byte-order mark before a "!" line in conversations/.gitignore no longer hides that line.
    OntoBoard refuses to save, because git would see the private conversations.
  - A released file holds only turns said while it was being saved. What was said before
    saving went on, or while it was off, stays private, and the first save says so.
- Settings:
  - The role section follows the ontology's project when the ontology gets its first file.
  - The project part and the provenance switch are read again whenever the view is shown or
    hidden, not only on a switch between the assistant's tabs.
  - A focused check box shows its focus around its words. In Protege's look and feel, keyboard
    users saw no focus on five switches.
- Assistant:
  - After two rows, the context chips scroll. Twelve chips left the conversation 7 px of a
    384 x 540 column; now they leave it as much room as four chips do.
  - On Java 13 and later, a chat that cannot connect is reported as unreachable, not as "sent
    nothing in 5 minutes".
  - From the 1.143.0 review: a chip you add yourself stays after the next sentence, and terms
    left out to fit a model's context are named in a notice.
- Benchmark:
  - The restrictions fixture no longer lets "max" pass for "exactly", or an answer without its
    class or datatype pass.
  - The text-to-axiom request names min, max, exactly and value, as well as some and only.
  - The cases were regenerated. Only the text-to-axiom requests and the restrictions fixture's
    cases changed, and every shipped case passes with its own held-back axiom.

Produced on Windows 11 Pro (10.0.26100), with tools/smoke.ps1 and -Dontoboard.selftest=true. The
verdict was read from what Protege logged. Protege 5.6.9 is the maintainer's own install, with
ontoboard-1.144.0.jar moved to ~/Documents/ontoboard-jar-backup; Protege 5.5.0 is the throwaway
copy. In each, this jar was the only ontoboard-*.jar in plugins. Each run was given
pizzabfo-edit.owl from a clean local clone of the pizza-bfo test project.

No live benchmark was run. The host check failed. The CPU ran at 73-100 % of its clock, with
