WHAT THIS RECEIPT DOES NOT COVER

Nothing here looks at a pixel or presses a button in the sheet editor, the board or a dialog: the
self-test constructs the two tabs and drives nine read-only menu items. What the sheet editor now
does - the folder it opens from each kind of file, following the active ontology, keeping unsaved
edits - is covered by 29 unit tests and was checked headless on pizza-bfo's real files, not
clicked through in Protege. The Release... and Template... fixes below are covered by unit tests,
not driven in the host.

CI on the release branch failed first, on Linux and on Windows, in one test, and had failed
since CI moved to Java 25 (09a8123): BuildsWithNothingInstalledTest installed a SecurityManager
to refuse every exec, and from Java 24 none can be installed (JEP 486). The plugin was not at
fault; the test could not run. It now keeps the SecurityManager where Java still allows one and
otherwise records the build with Java Flight Recorder's jdk.ProcessStart event, after showing
the recorder a start it must see. Checked on Java 11, 17 and 25 - and on 25 it fails, naming
the program, when one is started during the build. No plugin code changed.


FIXED IN 1.134.0 (each in docs/fixed.md, with how it was found)

- The sheet editor said "No templates yet" over nine templates one folder away. Opened from
  pizza-bfo's edit file it looked only in src/templates; its sheets are in kg/templates. It now
  tries four places in a fixed order - templates/ beside the file (src/templates instead, for an
  ODK edit file), then the project's src/templates, kg/templates and templates/ - with the
  project root found at most four levels up. It follows the active ontology, never replaces
  unsaved edits or a folder chosen by hand, creates nothing, and its toolbar names the folder.
  Check sheets... starts with that folder filled in, and Template...'s Browse opens in it.
- Every row of a sheet failed with "could not interpret" when its ID prefix (kg:) was not
  declared, and nothing said why: Template... now names the prefix, and the declared one that
  would settle it.
- Every row of a built graph "names 2 different things" in Check sheets... and the sheet
  editor's marks: a CURIE was compared with the IRI it expands to.
- ID ranges... offered a block under a name nothing mints with. The board, the sheet editor and
  the dialog now use one function for the editor's name.
- Template... recorded the person running it as the author of other people's terms, with
  provenance recording on: a class only an import declares, rdfs:label, a datatype. A term is new
  now only when neither the ontology nor anything it imports has it.
- Release... proposed 0.1.1 over a published 1.0.0, from an owl:versionInfo a release never
  updates, and would have released it, or 1.0.0 again over the published copy. It proposes the
  version after the newest release now, and refuses a semantic version at or below it.
- Record who edits terms... offered FOLLOW_THE_ONTOLOGY, ALWAYS and NEVER. Words now.
- Documentation... showed Widoco's ERROR lines over a page it had written: each known line is
  explained once.
