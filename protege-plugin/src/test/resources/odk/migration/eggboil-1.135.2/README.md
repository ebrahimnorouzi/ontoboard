# Test kitchen ontology

Application ontology for boiling eggs in a test kitchen

IRI: `https://example.org/eggboil/eggboil.owl`

## Editing

Open `src/ontology/eggboil-edit.owl` in Protege. That is the file you
edit; `eggboil.owl` is generated by the build.

## Building

From `src/ontology`, with `make` and ROBOT on your PATH:

```
make all        # reason, then report - and what a bare `make` runs
make reason     # classify with ELK into eggboil.owl
make report     # ROBOT quality report -> report.tsv
make sparql_test  # run every check in ../sparql over the edit file and its imports
make validate_profile  # fail if the ontology has left OWL 2 DL
make test       # what CI runs: reason, report, sparql_test and validate_profile
make prepare_release  # test, then a dated release (Release... in OntoBoard numbers them)
make clean      # delete the generated files
```

Custom targets go in `eggboil.Makefile`, which the build includes and
never overwrites. `Makefile` itself is generated - do not edit it.

Generated by OntoBoard.

The kitchen's notes on each boiling run are kept in `notes/`, which is not committed.
