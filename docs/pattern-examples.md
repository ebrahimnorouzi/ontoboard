# The patterns, their graphs and their examples

Every pattern page in the [library](patterns/index.md) shows two graphs and offers two downloads:
the pattern, a schema, and a worked example, data that instantiates it.

## The graph opens at level of detail 3

| | Shows |
|---|---|
| L0 | classes only, no edges |
| L1 | + the subclass hierarchy |
| L2 | + individuals, property nodes, object properties |
| **L3** | **+ OWL restrictions and SHACL constraints - the default** |
| L4, L5 | + datatype properties and literal nodes |
| L6 | + inferred triples |

L3 keeps the whole structure and hides the literals, which are most of a large pattern's nodes.
Raise it with the **LOD** control in the graph's toolbar. The default is set by
[docs/assets/pattern-lod.js](assets/pattern-lod.js), loaded from `mkdocs.yml`;
`tools/check-pattern-pages.py` checks the built pages in CI.

## Where the examples come from

An example is `patterns/<id>/example.ttl`:

```
python -I tools/make-pattern-examples.py        # write what is missing
python -I tools/check-pattern-examples.py       # the gate; CI runs this
```

The generator instantiates the pattern's own domains and ranges, following its imports into the
rest of the library, and never invents an axiom. The checker fails the build when an example does
not parse, uses a term the pattern does not declare, breaks a domain, range or property
characteristic, asserts both directions of an inverse pair, or is not connected.

## Adding a curated example

1. Edit `patterns/<id>/example.ttl`.
2. **Delete the comment lines that begin `# GENERATED by tools/make-pattern-examples.py`**, and
   say in two or three lines what the example shows - otherwise the generator may overwrite it.
3. Keep the shape the pattern dictates; use concrete names and readable labels.
4. Run `python -I tools/check-pattern-examples.py --only <id>`.

Every example in the library is curated. `template-instance` (no classes or properties) and
`spatial-graph-adapter-sga` (inconsistent itself) have none.

## Known issues

- **39 patterns declare no object property with both a domain and a range** - lists of classes
  rather than shapes; their graphs are unconnected dots.
- **Curated in 1.155.0**: every pattern passes ODK's quality report with its default profile
  - but for a licence, where its source states none (119, from the ODP portal) - names every term
  with a label, and is consistent and coherent; its `.owl` and `.ttl` say the same. Each pattern
  says what was changed in an `rdfs:comment` ("Curated by OntoBoard 1.155.0 ... Changes: ...");
  `patterns/licences.tsv` holds each source's licence, quoted from the source. A pattern's import
  module carries the licence (`dcterms:license`) and that the pattern was curated.
- **`metadata.json` names the source a pattern was harvested from**, which is not always the
  ontology it mostly uses (8 attributed to MWO, one built mostly from MWO terms).
- Harvest damage that was repaired: `Error1`…`Error6` placeholder classes in `airline`,
  `airline-owl` and `roledependentnames`; a duplicated, lower-case `transportEvent`; and BFO's own
  reversed definition of `preceded by`, corrected as an erratum in
  `tools/extract-bfo-patterns.py`.
